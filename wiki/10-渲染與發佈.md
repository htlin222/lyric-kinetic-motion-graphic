# 10. 渲染與發佈

## Deterministic renderer
- 用 `@napi-rs/canvas`（Skia）在 Node 裡畫，不需要瀏覽器，一幀約 100–300 ms。
- `renderFrame(t)`：所有東西都是 `t` 的純函數。隨機數用 seeded PRNG（mulberry32），不用 `Math.random`。
- 輸出：`canvas.data()`（raw RGBA）直接 pipe 給 `ffmpeg -f rawvideo -pix_fmt rgba -s 1920x1080 -r 30 -i -`，用 libx264 CRF 18 編碼。記得處理 `drain`，不然記憶體會爆。
- 字體：variable font（Playfair、Cormorant）的 weight 900 在 Skia 上可以正常使用。CJK 用 Noto Serif/Sans CJK TC Black OTF。

## 平行渲染
把影片切成 N 段同時渲染，再用 `ffmpeg -f concat -c copy` 接起來，最後 mux 音訊（AAC 256k，加 `-movflags +faststart`）。因為 renderer 是 deterministic 的，接縫不會有問題。

## 發佈（GitHub Release）
- 這個 session 環境不能直接呼叫 GitHub 的 Release API（403），也不能推 tag。
- 解法：用 `.github/workflows/release.yml`。推到 `release` branch（版本號讀 `VERSION` 檔）或推 `v*` tag 時，**CI 會重新渲染整支影片**，然後用 `GITHUB_TOKEN` 建立 release 並上傳 MP4。
- 這也證明了 deterministic 設計的價值：CI 渲染出來的影片和本機一模一樣。
- 對話裡的附件有 30 MB 上限，所以另外用 two-pass 做一個 720p、850 kbps 的預覽版。

## Wiki
`wiki/` 資料夾裡的頁面，會由 `.github/workflows/wiki.yml` 在每次 push 時同步到 GitHub Wiki。Wiki 必須先在網頁上建立第一頁，git 端點才會存在。
